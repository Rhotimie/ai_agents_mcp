Agents:
    - AI systems that can do work for you independently
    - ** AI systems where LLM controls the workflow **
    - LLM with tools in a loop to achieve a work flow

Agentic system 
    Agentic AI involves building harness around LLMs, crafting the inputs and interpreting the output, in a loop so that they can use tools, 
        and be autonomous
    reference:
        https://www.anthropic.com/engineering/building-effective-agents

    - Agent: are dynamic systems where LLM direct their own processes and tool usage, maining control over how they accomplished task
        - HUMAN --> LLM  --action-->  Environment
                        <--feedback--
                         --stop-->
        - Example:
            - claude code, codex, antigravity
            - gpt agent
            - sidekick
        - no pre-defined / fixed code path
        - open-ended structure
        - feedback loops

    - workflows: systems where LLM and tools are orchestrated through predefined code path
        - most common for production systems
        -Example: 
            - deep research feature in chatgpt
            - deep research workflow
        -Design pattern:
            - prompt chaining: decomposed into fixed sub task
                - INPUT --> LLM1 --> GATE --> LLM2 --> LLM3 --> OUT
            - Routing; Direct input into specialized subtasks, ensuring separation of concerns
                - INPUT --> LLM ROUTER --> LLM1 / LLM2 / LLM3 --> OUT 
            - Parallelization: breaking down tasks and running multiple subtasks concurrently
                - INPUT --> COORDINATOR --> LLM1 --> AGGREGATOR --> OUT 
                                        --> LLM2 -->
                                        --> LLM3 -->
            - Orchestrator-worker: complex task are broken down dynamically and combined
                - INPUT --> Orchestrator --> LLM1 --> Synthesizer --> OUT 
                                         --> LLM2 -->
                                         --> LLM3 -->
                    - LLM decides how to break down the tasks that run in parallel
                    - LLM decides how to combine the results and output it 
            - Evaluator-optimizer: LLM output is validated by another
                - also called LLM as a judge
                - INPUT --> LLM GENERATOR       --solution->            LLM EVALUATOR --accepted--> OUT
                                          <--rejected with feedback--


Risk of Agent Framework:
    - Unpredictable path 
    - Unpredictable output
    - Unpredictable costs

Risk Mitigation
    -- Monitor (Observability, Evals)
        - evaluation against business & technical goals
    -- Guardrails: ensures your agent behave safely, consistently, and within your intended boundaries
        -- evaluate inputs and output for consistency

Agent Trap:
    -- I need an agent for my business, instead of I need an agent to solve this business problems
    -- Not incorporating business goal evaluation to confirm the agent is effective
    -- Anthropomorphizing: treating agent like they are humans
        - Agent architectures that assign human like responsibilities to agent 
        - Trading manager agent should not translate to the below human-like architecture ==>
            Market research agent + Trader Agent + Risk Manager Agent 
        - solution:
            - start simple with just one LLM and measure performance against a business obejective
            - then diveide into more LLM calls to improve performance

context engineering:
    The art of providing all the context for the task to be plausibly solvable by the LLM.
    context:
        - instructions / system prompt: overall framing of what the agent has to do
        - user prompt: current message to llm / question
        - Available tools
        - structured output: formating output in a predefined manner, accessible through tools
        - Retrieved information (RAG): querying useful relevant information from knowledge base of extra data and shove it into the prompt
        - state / history (short-term memory): conversation history
        - long-term memory: any other information from prior conversations stored that might be relevant, accessible through tools, RAG, system prompt
    refernce:
        https://www.philschmid.de/context-engineering

Offerings:
    - CrewAI AMP / Enterprise: multi-agent platform for deploying, running and monitoring Agentic AI 
    - CrewAI Studio: A no-code / low-code product for creating multi-agent solutions, similar to n8n 
    - CrewAI open-source framework: orchestrate high performing AI agents with ease and scale 

CrewAI framework:
    It is lightweight but more opinionated framework the OpenAI Agents SDK, more terminology and marginally more prescriptive
    - CrewAI Crews(the intelligence): 
        Autonomous solutions with AI teams of Agents with different roles 
        crew are the "teams" that do the heavy lifting. 
        you can trigger a crew to tackle a complex problem requiring creativity and collaboration
    - CrewAI Flows(the backbone):
        structured automations by dividing complex tasks into precise workflows
        Think of a flow as the "manager" or the "process definitions" of your application.
        it defines the steps, the logic, and how data moves through your system.

CrewAI CORE CONCEPTS
    - Agent(autonomous units with an LLM, a role, a goal, a backstory, memory, tools):
        - role: purpose of the agent
        - goal: what it is trying to achieve and it's success
        - backstory: what background story might be relevant to the agent
        - tools:
            ref: https://docs.crewai.com/v1.15.14/en/concepts/tools

    - Task(more like a user prompt): 
        - specifc assignment to be carried out
            - description
            - expected_output
            - agent
            - context(if not specified, every other prior task is added as context)
            - output_file

    - crew(bunch of agents and tasks):
        - sequential(similar to orchestration by code): run tasks in the order they are defined
        - hierarchical(similar to orchestration by LLM): use a manager LLM to assign, decide the order that they are run in

YAML configuration:
    - Agents and task can be created by code, setting the backstory, description, expected output, etc 
    - or define each in yaml file that's provided when you create the project

crewai traces enable:
    - turn on traces
    - if enabled, after crewai run, link to view the traces will the shown

steps to creating vrewai project:
    - crewai create crew my_project 
    - fill the config yaml files(agent.yml and task.yml) to define Agents and Tasks 
    - complete the crew.py module to create the Agents, Tasks and Crew, referencing the config
    - update main.py to set inputs
    - crewai run
